# 错误记录

## 2026-05-14: 删除卡片预览功能

### 事实链

1. 用户报告浏览器不能滚动
2. 我假设原因是 iframe 预览导致卡顿
3. 我删除了卡片预览功能（card-preview CSS、HTML、initPreviews 函数）
4. 用户澄清：不能滚动是指滚动条不可见，不是卡顿
5. 我没有恢复预览，而是继续修补（加 flex-shrink、改滚动条宽度）
6. 用户指出卡片高度变小（因为预览被删了）
7. 我恢复了预览功能

### 错误分析

| 步骤 | 错误 |
|------|------|
| 诊断 | 未确认"不能滚动"的具体表现，直接假设是卡顿 |
| 方案选择 | 选择删除功能而非优化（如限制同时加载数量） |
| 用户澄清后 | 未回退修改，继续在错误方向修补 |
| 惯性 | 已经动手删了，就不想改回来 |

### 正确做法

1. 用户说"不能滚动"时，应先问：是看不到滚动条？还是内容不动？还是浏览器卡住？
2. 即使是卡顿，也应优化加载策略，而非删除功能
3. 用户澄清"不是卡顿"后，应立即恢复被删的功能

### 待解决

- 如何在修改前更好地确认问题
- 如何在新信息出现时及时回退错误修改

## 2026-05-14: iframe 滚动条显示为灰线

### 现象

卡片预览底部有一条灰色横线，看起来像边框。

### 诊断过程

1. 最初误认为是 `card-preview` 的边框 → 去掉边框，无效
2. 用户指出是 iframe 底部的线
3. 用户要求将 border-bottom 改成红色验证 → 灰线仍在
4. 用户判断"看起来像滚动条"
5. 隐藏 iframe 滚动条后，灰线消失

### 根因

iframe 有默认滚动条，容器 `overflow: hidden` 截断后，滚动条底部露出来显示为灰线。

### 修复

注入 CSS 到 iframe：`::-webkit-scrollbar { display: none; } html, body { scrollbar-width: none; overflow: hidden; }`
